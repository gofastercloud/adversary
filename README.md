# ADVERSARY

A roguelike deckbuilder that teaches threat modelling and blue-team practice. You are the defender: you play
**controls** from a deck built on NIST CSF 2.0 × STRIDE, an AI **adversary** plays a deck compiled from real MITRE ATT&CK
techniques, and a Balatro-style run (3 acts, relics, doctrines, maturity levels, bosses) wraps it. Everything the game
claims is linked to authoritative sources: ATT&CK, EMB3D, D3FEND-style mitigations, NIST, OWASP, IEC 62443, APRA, SOCI,
the Essential Eight.

Educational, Australian-context (SOCI, AESCSF, APRA CPS 234/230, Essential Eight, OAIC NDB), with one scenario pack per
domain: **Enterprise, Utilities, OT & ICS, Banking, Cloud (AWS), Third-Party Risk, AppSec & Supply Chain**.

## Run it

```bash
npm install
npm run dev          # builds, serves http://localhost:5173 with an in-process API (in-memory store). No Docker, no AWS.
npm test             # engine, API, DynamoDB (Dynalite) and pack smoke tests
npm run ci           # validate content, tests, icon check, build
```

Node 22+. First-time players get a guided tutorial battle; the in-game Guide has the rules and every concept's sources.

## What is in the box

| Area | Where | Notes |
|---|---|---|
| Rules engine | `engine/` | Pure, deterministic, JSON-serialisable, counter-based hash RNG. The same code runs in the browser and in the Lambda that verifies runs. |
| Content | `content/core`, `content/packs` | Cards, relics, doctrines, events, achievements (122, 20 hidden), tuning, adversary meta, scenario packs. Generated by `scripts/gen-*.mjs` and `scripts/packs/*.mjs`. |
| Real data | `data/` | ATT&CK, EMB3D, CTID mappings, Attack Flow incidents, baseline prevalence, 47 adversary decks and dossiers. See [docs/DATA_SOURCES.md](docs/DATA_SOURCES.md). |
| SPA | `web/` | Preact + htm, esbuild, strict CSP, self-hosted fonts and icons, synthesised audio. |
| API | `api/` | Two Lambda handlers (read/write): verified-run leaderboard, daily challenge, profile sync. |
| Infrastructure | `infra/` | CDK (TypeScript): S3 + CloudFront (OAC), HTTP API, ARM64 Node 22 Lambdas, single-table DynamoDB. |

## Honest limits

- Balance is a work in progress. Bots win far too often at tier 1 and too rarely against apex adversaries with some
  doctrines; use `npm run sim` to see current numbers.
- The Docker paths (`docker-compose.yml`, Floci) were not run in the authoring sandbox (no Docker daemon). The DynamoDB
  code path is tested against Dynalite instead.
- Leaderboards are verified by replaying every action server-side, but player identity is trust-on-first-use, not
  authentication. Do not treat it as an assessment record.
- Technique-to-STRIDE mapping, card statistics, goals and assessed intents are gameplay interpretations. Each is labelled
  as such in the UI; the technique IDs, tactics, mitigations and procedure examples are MITRE data.
